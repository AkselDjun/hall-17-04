# HALL 17.04 — сайт пространства для событий

Одностраничный сайт HALL 17.04 (Барановичи, ул. Ленина, 12): зал для свадеб, юбилеев и дней рождения, площадка для обучения и фотостудия. Концепция «Премьера» — нуарное кино: киноплёнка в первом экране, «сцены» вместо разделов, предложения в виде билетов, касса вместо формы.

**Демо:** https://akseldjun.github.io/hall-17-04/

![Первый экран](public/og.jpg)

## Стек

- [Next.js 16](https://nextjs.org/) (App Router, статический экспорт) + React 19 + TypeScript
- CSS Modules и CSS-переменные — без UI-фреймворков, вся вёрстка своя
- Шрифты Cormorant Garamond, Manrope и IBM Plex Mono подключены локально через Fontsource — сторонних запросов нет
- Фото: скрипт на `sharp` нарезает их в AVIF и WebP шириной 320–1600 px. Сайт отдаёт AVIF, а старым браузерам — WebP, и каждый экран берёт ближайший нужный размер. Пока фото грузится, на его месте видно размытое превью. Первые кадры плёнки загружаются с высоким приоритетом.
- Анимации на CSS, без библиотек: блоки плавно появляются при прокрутке (`IntersectionObserver`). Если в системе включено «уменьшить движение», анимации отключаются. Без JavaScript весь контент тоже виден.
- Хостинг: GitHub Pages, деплой через GitHub Actions

## Запуск

Нужен Node.js 20.9+ (версия для CI указана в `.nvmrc`).

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # статическая сборка в папку out/
npm run preview    # посмотреть сборку локально
npm run lint
npm run typecheck
```

`dev` и `build` сначала запускают `npm run images`. Скрипт делает AVIF- и WebP-версии фото из `assets/photos` в `public/images`, пишет размеры и превью в `src/content/photos.json` и пересобирает только изменённые фото. Первая нарезка занимает несколько минут: AVIF кодируется долго.

## Как менять контент

Тексты, цены, контакты, отзывы и подписи к фото находятся в `src/content/site.ts`. Код при этом трогать не нужно.

- **Цены.** Лежат в `offers.items` в поле `price`, например `"от 2 000 BYN"` или `"от 120 BYN / час"`. Цифры сами попадают в разметку для поисковиков: с «от» как минимальная цена, без «от» как точная.
- **Фото.** Положите jpg в `assets/photos` и укажите имя файла без расширения в `site.ts` (например, `src: "reel-01"`).
- **Форматы в форме.** Список задаётся в `bookingFormats`. Кнопки «Выбрать» на билетах и «Подробнее» в форматах сами подставляют нужный формат в форму.

## Форма заявки и Telegram

Устроено так же, как в alextvsat:

1. Форма отправляет заявку (`POST` с JSON) на `/api/contact.php` на том же сервере.
2. Скрипт `public/api/contact.php` пересылает её в Telegram-бота.

```json
{ "name": "Анна", "phone": "+375291234567", "date": "17.04.2027", "guests": "40", "format": "Свадьба под ключ", "website": "" }
```

Токен бота не попадает ни в сборку, ни в репозиторий. Он хранится в файле `telegram-config.php` на уровень выше `public_html`, куда нет доступа из браузера. Создайте этот файл один раз по образцу `telegram-config.example.php`, указав токен бота и id чата.

Что проверяет скрипт:

- имя;
- телефон белорусского формата;
- дату, количество гостей и формат из списка.

Ботов он отсекает по скрытому полю `website` и принимает не больше 5 заявок с одного IP за 10 минут. Если скрипт или Telegram не ответили, на сайте появляется плашка «Заявка не отправилась», а введённые данные остаются в полях.

На GitHub Pages PHP не работает, поэтому демо собирается с `NEXT_PUBLIC_BOOKING_DEMO=true`: форма имитирует отправку и показывает билет «Заявка принята». Состояние ошибки в демо можно посмотреть по ссылке https://akseldjun.github.io/hall-17-04/?error. В `npm run dev` форма тоже работает в демо-режиме.

### Политика конфиденциальности

Политика лежит на странице `/privacy/` и сделана по образцу сайта «Моринское» (morinskoe-site). Текст хранится в `src/content/policy.ts`. Ссылка на неё есть в подвале и в форме: заявка не отправится, пока не стоит галочка согласия на обработку данных и их передачу в Telegram. Скрипт `contact.php` тоже проверяет согласие и отклоняет заявку без него. В сообщении в Telegram есть строка о полученном согласии.

### Cookie

Окно cookie сделано как на «Моринском»: внизу экрана появляется баннер с кнопками «Принять все», «Только необходимые» и «Настроить». Выбор хранится в cookie `hall1704_consent` один год. Изменить его можно по ссылке «Настройки cookie» в подвале.

Карта Яндекса ставит свои cookie, поэтому до согласия вместо неё стоит заглушка с кнопкой «Показать карту». Яндекс Метрика подключается, только если задан `NEXT_PUBLIC_METRIKA_ID` и посетитель разрешил аналитику. Пункт «Аналитика» в окне и в политике появляется сам, когда номер счётчика задан.

## SEO

Главная собрана под запрос «банкетный зал в Барановичах» и соседние: «зал для свадьбы», «юбилей», «день рождения», «аренда зала».

- **Заголовок и описание** страницы задаются в `meta` в `src/content/site.ts`. Строка «Банкетный зал в Барановичах» над главным заголовком — часть H1, она лежит в `hero.eyebrow`.
- **Разметка schema.org** собирается в `src/lib/schema.ts`: `LocalBusiness` + `EventVenue` с адресом, индексом, координатами, вместимостью, оборудованием и услугами, плюс `WebSite`. Когда в `offers.items` появятся цены вида «от 1500 BYN», они сами попадут в разметку как минимальная цена услуги.
- **Иконки:** `icon.svg`, `favicon.ico`, `apple-icon.png` в `src/app/`, иконки 192 и 512 px в `public/icons/` и `manifest.webmanifest`.
- **Индексация:** `robots.txt` и `sitemap.xml` собираются сами. Пока `NEXT_PUBLIC_INDEXABLE` не равен `true`, сайт закрыт от поисковиков.
- **Подтверждение прав** в Яндекс Вебмастере и Google Search Console: задайте коды в `NEXT_PUBLIC_YANDEX_VERIFICATION` и `NEXT_PUBLIC_GOOGLE_VERIFICATION`, мета-теги появятся сами.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_BASE_PATH` | Префикс пути, например `/hall-17-04` для GitHub Pages. На своём домене оставьте пустым |
| `NEXT_PUBLIC_SITE_URL` | Полный адрес сайта для canonical, Open Graph и разметки schema.org |
| `NEXT_PUBLIC_BOOKING_DEMO` | `true` — форма только имитирует отправку (для GitHub Pages) |
| `NEXT_PUBLIC_INDEXABLE` | `true` открывает сайт поисковикам. По умолчанию стоит `noindex`, пока это демо |
| `NEXT_PUBLIC_METRIKA_ID` | Номер счётчика Яндекс Метрики. Пусто — аналитики нет. На GitHub Pages берётся из переменной репозитория `METRIKA_ID` |
| `NEXT_PUBLIC_YANDEX_VERIFICATION` | Код подтверждения из Яндекс Вебмастера (значение `content` из мета-тега) |
| `NEXT_PUBLIC_GOOGLE_VERIFICATION` | Код подтверждения из Google Search Console (значение `content` из мета-тега) |

## Деплой

При каждом пуше в `main` workflow `.github/workflows/deploy.yml`:

1. проверяет код линтером и TypeScript;
2. собирает сайт с нужным префиксом пути;
3. выкладывает готовую сборку в ветку `gh-pages`.

GitHub Pages раздаёт сайт из этой ветки (Settings → Pages → Deploy from a branch → `gh-pages` / root). Ветку `gh-pages` вручную не правят: при каждом деплое она перезаписывается.

Папку `out/` можно выложить на любой статический хостинг: Netlify, Vercel, Cloudflare Pages или обычный сервер. Если сайт открывается в корне домена, `NEXT_PUBLIC_BASE_PATH` оставьте пустым.

## Хостинг hoster.by

Боевой адрес сайта — https://hall1704.of.by. Старый адрес 1704.of.by, если он подключён к той же папке, перенаправляется на новый правилом в `.htaccess`. Сайт заливается вручную, как и alextvsat.

1. Соберите сайт для домена:

   ```bash
   NEXT_PUBLIC_SITE_URL=https://hall1704.of.by NEXT_PUBLIC_INDEXABLE=true npm run build
   ```

2. Загрузите всё содержимое папки `out`, кроме `.nojekyll`, в корневую папку сайта (обычно `public_html`) через файловый менеджер панели или SFTP. Скрытый файл `.htaccess` тоже нужен: он включает HTTPS, убирает `www`, сжимает файлы и настраивает кеш. Скрипт формы окажется в `public_html/api/contact.php`.
3. Один раз создайте `telegram-config.php` на уровень выше корневой папки сайта, то есть рядом с `public_html`, а не внутри неё.
4. До загрузки включите для домена SSL-сертификат: `.htaccess` перенаправляет всех на https.
