# HALL 17.04 — сайт пространства для событий

Одностраничный сайт HALL 17.04 (Барановичи, ул. Ленина, 12): зал для свадеб, юбилеев и дней рождения, площадка для обучения и фотостудия. Концепция «Премьера» — нуарное кино: киноплёнка в первом экране, «сцены» вместо разделов, предложения в виде билетов, касса вместо формы.

**Демо:** https://akseldjun.github.io/hall-17-04/

![Первый экран](public/og.jpg)

## Стек

- [Next.js 16](https://nextjs.org/) (App Router, статический экспорт) + React 19 + TypeScript
- CSS Modules и CSS-переменные — без UI-фреймворков, вся вёрстка своя
- Шрифты Cormorant Garamond, Manrope и IBM Plex Mono подключены локально через Fontsource — сторонних запросов нет
- Фото: `next/image` со своим загрузчиком и WebP-версиями 480/960/1600 px, которые собирает скрипт на `sharp`
- Хостинг: GitHub Pages, деплой через GitHub Actions

## Запуск

Нужен Node.js 20.9+ (версия для CI указана в `.nvmrc`).

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # статическая сборка в папку out/
npm run preview    # посмотреть сборку локально
npm run lint
npm run typecheck
```

`dev` и `build` сначала запускают `npm run images`. Скрипт делает WebP-версии фото из `assets/photos` в `public/images` и пересобирает только изменённые файлы.

## Структура


## Как менять контент

Тексты, цены, контакты, отзывы и подписи к фото находятся в `src/content/site.ts`. Код при этом трогать не нужно.

- **Цены.** Сейчас вместо них стоят заглушки `от [цена] BYN` в `offers.items`.
- **Фото.** Положите jpg в `assets/photos` и укажите имя файла без расширения в `site.ts` (например, `src: "reel-01"`).
- **Форматы в форме.** Список задаётся в `bookingFormats`. Кнопки «Выбрать» на билетах и «Подробнее» в форматах сами подставляют нужный формат в форму.

## Форма заявки

Без настройки форма работает в демо-режиме:

- проверяет имя и телефон (маска `+375 XX XXX-XX-XX`) и формат даты;
- 1,3 секунды показывает «Отправляем…»;
- затем показывает билет «Заявка принята».

Чтобы заявки реально приходили, задайте адрес приёмника в переменной `NEXT_PUBLIC_BOOKING_ENDPOINT`. Подойдёт Formspree, Getform, вебхук Make/Zapier или своя функция, которая пересылает заявку в Telegram. Форма отправляет `POST` с JSON:

```json
{ "name": "Анна", "phone": "+375291234567", "date": "17.04.2027", "guests": "40", "format": "Свадьба под ключ", "source": "https://…" }
```

Если сервер ответит ошибкой или пропадёт сеть, появится плашка «Заявка не отправилась». Введённые данные при этом не стираются. Чтобы посмотреть это состояние, откройте сайт с параметром `?error`: https://akseldjun.github.io/hall-17-04/?error

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_BASE_PATH` | Префикс пути, например `/hall-17-04` для GitHub Pages. В CI подставляется автоматически |
| `NEXT_PUBLIC_SITE_URL` | Полный адрес сайта для canonical, Open Graph и разметки schema.org |
| `NEXT_PUBLIC_BOOKING_ENDPOINT` | Адрес, куда отправлять заявки. Если не задан — демо-режим |
| `NEXT_PUBLIC_INDEXABLE` | `true` открывает сайт поисковикам. По умолчанию стоит `noindex`, пока это демо |

В GitHub эти значения задаются как переменные репозитория (Settings → Secrets and variables → Actions → Variables): `BOOKING_ENDPOINT` и `INDEXABLE`.

## Деплой

При каждом пуше в `main` workflow `.github/workflows/deploy.yml`:

1. проверяет код линтером и TypeScript;
2. собирает сайт;
3. публикует его на GitHub Pages.

В настройках репозитория должно быть выбрано Settings → Pages → Source: **GitHub Actions**.

Папку `out/` можно выложить на любой статический хостинг: Netlify, Vercel, Cloudflare Pages или обычный сервер. Если сайт открывается в корне домена, `NEXT_PUBLIC_BASE_PATH` оставьте пустым.
